> 版本:v1.0 · 日期:2026-09-05
> 依据:代码库全量走读(约 5800 行,后端 Node.js 22 + Express + node:sqlite,前端 Vue 3)+ 竞品调研(彩虹聚合 DNS/dnsmgr、HiDNS、DNSControl、octoDNS、PowerDNS-Admin、ddns-go、Domain Admin、Uptime Kuma 等)

---

## 一、产品概述

### 1.1 产品定位
自托管轻量 DNS 运维面板:统一管理 Cloudflare、DNSPod(独立版)、阿里云 ESA 的域名解析记录,面向个人开发者与小团队运维,解决"多控制台来回切换、操作低效易错、故障无法自动止损"的痛点。

### 1.2 目标用户与典型场景
- **个人开发者(多域名散落多家)**:"20 个域名分散在 CF/腾讯云/阿里云,每改一条记录要记三套控制台交互。"
- **小团队运维**:换服务器需要给十几个域名批量改 A 记录,手动逐条改必出错。
- **家庭宽带/NAS 用户**:公网 IP 动态变化,需要 DDNS,同时想在统一面板看解析状态。
- **自托管爱好者**:面板暴露公网,关注安全(审计、限流、2FA)与可恢复性(误删回滚)。

### 1.3 现状基线(已实现)
账户管理(三服务商、保存时凭证即时校验、Token AES-256-GCM 加密落库)、记录 CRUD(统一 common 模型、CF 云朵开关、DNSPod 分线路/启停、ESA 边缘加速)、批量操作(删除/启停/加速/四维批量编辑+变更预览)、JSON/CSV 导入导出(预览+逐条进度)、公网解析生效检测(1.1.1.1/8.8.8.8)、操作审计日志、登录限流+检测限流、暗色模式/PWA/移动端适配、Docker 单容器部署。

## 三、新功能需求(New Features)

### 梯队一:从"记录管理工具"到"解析运维平台"的分水岭

#### F1 变更历史与一键回滚 ⭐ 最高优先
- **用户故事**:作为运维,我误删了整组 MX 记录导致邮件中断,我需要在 30 秒内恢复到误操作前的状态。
- **需求**:
  - 每次记录增/删/改前保存 zone 快照(或记录级 before/after)至本地 SQLite;
  - 变更历史页:按域名+时间查看 diff(对齐现有批量编辑的 diff 组件复用);
  - 一键回滚单条记录至历史版本(受 locked 保护约束);
  - 快照保留策略(默认 90 天/每域最近 200 次变更)。
- **验收**:删除任意记录后可在历史中找到并可恢复;回滚操作本身入审计。
- **竞品参照**:DNSControl(Git+preview)、octoDNS(plan)、Cloudflare 控制台。

#### F2 通知渠道体系
- **用户故事**:面板凌晨批量改记录失败了/检测发现解析异常,我需要第一时间收到推送而不是次日才发现。
- **需求**:
  - 通知设置页:自定义 Webhook(通用 JSON 模板,底座)→ Server酱 / 钉钉 / 飞书 / 企业微信群机器人 → Telegram Bot / SMTP 邮件,按此顺序分批交付;
  - 触发事件:批量操作失败汇总、检测异常(含 F3 周期检测)、DDNS 更新成败、账户 Token 失效、登录异常(连续失败);
  - 每渠道"发送测试"按钮;发送失败静默重试一次并记录。
- **竞品参照**:Uptime Kuma(90+ 渠道范式)、ddns-go、彩虹聚合 DNS。

#### F3 解析监控告警(周期检测)
- **用户故事**:我希望面板周期性检测关键域名解析是否与配置一致、指向的服务是否存活,异常时自动通知。
- **需求**:
  - 复用 `dnscheck.js` 与 `tools/dns-lookup` 做调度化:按域配置检测周期(5/15/30/60 分钟);
  - 检测维度:公网解析一致性(修复 D2/D3 前提下)+ 可选 TCP/HTTP(S) 存活探测记录值;
  - 异常状态在域名列表标红,连续 N 次异常触发 F2 通知;恢复时发恢复通知;
  - 检测历史(近 7 天可用率)。
- **竞品参照**:彩虹聚合 DNS 容灾切换、DNSPod D 监控、Domain Admin。
- **后续延伸(独立需求 F3b 容灾切换)**:异常自动暂停/切换记录(dnsmgr 范式),先做告警后做自动动作,自动动作必须可开关、可回滚。

#### F4 开放 REST API + Personal Access Token
- **用户故事**:我想在 CI/脚本/certbot DNS-01 中调用面板 API 统一操作三家服务商,而不是各自引 SDK。
- **需求**:
  - PAT 管理(创建/命名/过期时间/最近使用/吊销),`Authorization: Bearer`;
  - 开放端点复用现有路由语义:账户只读、zones/records CRUD、检测触发;
  - PAT 操作全量入审计;限流独立配额;
  - API 文档页(Swagger UI 或简单 markdown)。
- **依赖**:多用户体系可后置,PAT 先绑定 admin。

#### F5 定时任务 / 计划解析
- **用户故事**:活动凌晨 2 点结束,我希望面板到点自动把记录切回原值/下线,而不是定闹钟手动改。
- **需求**:
  - 任务类型:一次性(at)与周期(cron);动作:启停/改值/删除指定记录(复用批量编辑的变更计算);
  - 执行前预览、执行结果入审计+F2 通知;
  - 与 F1 变更历史联动(可回滚定时任务造成的变更)。
- **竞品参照**:dnsmgr 定时切换。

### 梯队二:差异化与安全补强

#### F6 多用户 + 按域名授权(RBAC)
- **需求**:admin 之外增加普通用户;用户↔域名多对多授权;只读角色(可看不可改);登录/操作按用户审计(users 表已有多行能力,缺 role 与授权表);会话与限流按用户隔离。
- **竞品参照**:dnsmgr(按用户分配域名)、HiDNS(RBAC+细粒度 Token)、PowerDNS-Admin(zone 级)。
- **说明**:README Roadmap 已列"多用户与只读角色",audit_logs 已预留 username 维度。

#### F7 TOTP 两步验证(2FA)
- **需求**:TOTP 绑定(二维码+恢复码)、登录二次校验;可选信任设备 30 天。
- **理由**:自托管面板常暴露公网,单密码 + IP 限流不足以防凭证泄露;TOTP 实现成本低(零依赖可用 node:crypto 自实现或引 otplib)。
- **竞品参照**:HiDNS(TOTP/WebAuthn)、PowerDNS-Admin。

#### F8 DDNS 动态解析
- **需求**:对指定 A/AAAA 记录,周期检测本机/指定接口公网 IP(4/6),变化时自动更新(多服务商通用);IP 变化与更新成败走 F2 通知;支持自定义检测 URL(应对 CGNAT)。
- **竞品参照**:ddns-go、deSEC dynDNS。README Roadmap 已列。

#### F9 域名分组与标签
- **需求**:域名打标签(生产/测试/个人…),侧栏按组过滤,批量操作可按组发起。实现成本低、组织价值高。

#### F10 多地解析拨测
- **需求**:现有单点检测升级为多地域(至少境内+境外各一节点,通过公共 DNS over HTTPS 端点实现:阿里/Google/CF DoH),展示各视角解析结果与生效进度。
- **说明**:零后端依赖可用 DoH JSON API 实现,是国内部署下对 D2 硬编码问题的更彻底解法。

#### F11 域名 / SSL 证书到期监控
- **需求**:对已纳管域名做 WHOIS/注册商 API 到期查询(缓存+竞速)与 443 证书链到期探测;到期前 30/7/1 天分级告警(走 F2)。与解析管理同屏呈现资产视图。
- **竞品参照**:HiDNS(续期管理)、Domain Admin(立项即为此痛点)。
